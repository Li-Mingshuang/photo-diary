# 03-设计文档：光影日记（PhotoDiary）

> 版本：v1.1 · 2026-10-07（迭代二：当日小结/搜索/可取消/首次引导）

## 1. 产品定位

拍照（或从相册选一张照片）→ AI 看一眼照片 + 时间地点 → 自动写好一段日记 → 按天归档成 Markdown。全程一次点击，生成的文字可改、可重新生成。

## 2. 总体架构

```
┌───────────────────────── SwiftUI Views ─────────────────────────┐
│ ContentView（按天列表）  DayDetailView（条目卡片流）              │
│ AddEntryView（生成+编辑）  SettingsView（LLM 配置）               │
└──────┬───────────────┬──────────────────┬───────────────────────┘
       │               │                  │
┌──────▼──────┐ ┌──────▼───────┐ ┌────────▼─────────┐ ┌────────────┐
│ DiaryStore  │ │ PhotoImporter│ │   LLMService     │ │ Location   │
│ (内存索引+   │ │ EXIFReader   │ │ (OpenAI 兼容      │ │ Service /  │
│  磁盘md归档) │ │ CameraPicker │ │  Chat Completions)│ │ Geocoder   │
└──────┬──────┘ └──────────────┘ └────────┬─────────┘ └────────────┘
       │                                  │
┌──────▼─────────────────┐      ┌─────────▼──────────┐
│ Documents/diaries/     │      │ LLMConfigStore     │
│  ├─ 2026-10-07.md      │      │ UserDefaults(配置)  │
│  └─ images/*.jpg       │      │ Keychain(API Key)  │
└────────────────────────┘      └────────────────────┘
```

设计要点：

- **无第三方依赖**：全部系统框架（SwiftUI / PhotosUI / Photos / ImageIO / CoreLocation / Security），包体小、无供应链风险。
- **文件即数据库**：Markdown 文件是唯一持久化事实源，App 启动时解析重建内存索引；任何一台机器上用文本编辑器都能读懂、手改不丢数据。
- **纯函数可测**：请求构造（`LLMService.makeRequest/makeBody/parseResponse`）、Markdown 编解码（`MarkdownDiaryCodec`）、Prompt 拼装（`PromptBuilder`）均为无状态纯函数，单测无需网络与 UI。
- **位置是加分项不是必需**：定位未授权/超时/反地理失败均静默降级，不阻断写日记主流程。

## 3. 核心数据模型

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| `DiaryEntry` | id, createdAt, text, imageFileName?, locationName?, latitude?, longitude?, isDaySummary | 一条日记（一次拍照/导入）；isDaySummary 为「当日小结」条目 |
| `DiaryDay` | key(yyyy-MM-dd), entries[] | 一天，对应一个 md 文件 |
| `EntryDraft` | image, takenAt, location?, locationName? | 保存前的草稿 |
| `LLMPreset` | id, name, baseURL, model, supportsVision | LLM 接入配置 |

## 4. Markdown 归档格式规范

每天一个文件 `YYYY-MM-DD.md`：

```markdown
# 2026年10月7日 星期三

## 14:30 · 上海市 · 静安区 · 静安公园

![照片](images/IMG_20261007-143000-ab12cd34.jpg)

下午路过静安公园，阳光把银杏叶照得透亮……

---

## 20:05

晚上随手拍的一张照片。
```

规则：

- 一级标题为日期（中文 + 星期），解析时忽略；
- 每条日记一个二级标题 `## HH:mm[ · 地点]`，时间精确到分钟（解析重建 createdAt 时秒归零）；
- 「当日小结」是特殊条目，标题固定 `## 当日小结`，无时间与地点，渲染/解析均排在普通条目之前，createdAt 约定为当天 23:59；
- 图片行格式固定 `![照片](images/<文件名>)`，文件落盘在 `diaries/images/`（最长边 2048px、JPEG 0.85）；
- 条目之间以 `---` 分隔；正文支持多行；
- 正文与语法冲突的行（`---`、条目标题、`## 当日小结`、图片行）渲染时加 `\\` 转义，解析还原；
- 解析对无法识别的行容错跳过（文档标题、游离文本等）。

## 5. LLM 调用设计

- 端点：`{baseURL}/chat/completions`，POST，`Authorization: Bearer <key>`，60s 无数据超时（流式每收一块重置）；
- 消息：单条 user 消息，content 数组 = 文本块（PromptBuilder 填充后的模板）+ 可选图片块（base64 data URL，上传前缩到最长边 1280px、JPEG 0.7）；「当日小结」支持多图（单图 1024px、JPEG 0.6），prompt 用 `DefaultPrompt.daySummaryTemplate`（占位符 `{count}` `{timeline}`）；
- 流式请求（SSE）支持用户取消：`AsyncThrowingStream.onTermination` 里取消底层网络 Task，取消后保留已生成的部分文本；
- 非视觉预设自动丢弃图片块，退化为「仅根据时间地点写一段」；
- 响应兼容两种 content 形态（纯字符串 / 分块数组）；错误响应提取 `error.message` 展示给用户；
- 默认 Prompt 模板见 `DefaultPrompt.template`，占位符：`{datetime}` `{date}` `{time}` `{location}`（先替换 `{datetime}` 再 `{date}` 避免误匹配）。

## 6. UI 设计

| 页面 | 内容 |
| --- | --- |
| 首页（按天列表） | 大标题「光影日记」；每行 = 缩略图 + 日期标题 + 「N 条记录 · 摘要」；`.searchable` 搜索（正文/地点/日期）；未配 Key 时空态按钮/常驻横幅引导去设置；左上设置、右上 +（拍照/相册菜单） |
| 新增页 | 照片预览 → 时间/地点元数据 → 自动生成（进度态、可停止）→ 可编辑正文 → 保存/取消/重新生成；缺 Key 时给出直达设置入口 |
| 日记详情页 | 条目卡片流（时间·地点 / 图片 / 正文；当日小结为橙色「当日小结」卡片置顶）；条目菜单：编辑、重新生成、删除；右上：当日小结（多图合并生成一篇，可停止）、分享导出当天 md |
| 设置页 | 服务预设、Base URL/模型（自定义时可编辑）、API Key（SecureField，附 DeepSeek 申请链接）、Prompt 模板编辑器（可恢复默认）、测试连接 |

视觉：系统字体 + 卡片圆角 + SF Symbols，浅色/深色自适应，极简无品牌色。

## 7. 隐私与权限

| 权限 | 用途 | 降级 |
| --- | --- | --- |
| 相机 | 拍照 | 无相机（模拟器）时隐藏入口 |
| 相册（受限即可） | 选照片及读取其时间地点 | 仅影响导入入口 |
| 定位（使用时） | 拍照时记录地点 | 拒绝则日记无地点信息 |

- API Key 仅存 Keychain；图片仅用户触发生成时上传给所配置的服务；日记与照片全部本地存储，可用文件 App 访问/备份。
