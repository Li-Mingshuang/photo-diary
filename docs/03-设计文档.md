# 03-设计文档：光影日记（PhotoDiary）

> 版本：v1.5 · 2026-10-08（迭代六：语音日记——转录 + AI 整理）

## 1. 产品定位

拍照（或从相册选一张照片）→ AI 看一眼照片 + 时间地点 + 你的个人画像 → 自动写好一段日记 → 按天归档成 Markdown。全程一次点击，生成的文字可改、可重新生成；画像随使用沉淀，AI 的文风越用越像你。

## 2. 总体架构

```
┌───────────────────────── SwiftUI Views ─────────────────────────┐

└──────┬───────────────┬──────────────────┬───────────────────────┘
       │               │                  │
┌──────▼──────┐ ┌──────▼───────┐ ┌────────▼─────────┐ ┌────────────┐
│ DiaryStore  │ │ PhotoImporter│ │   LLMService     │ │ Location   │
│ (内存索引+   │ │ EXIFReader   │ │ (OpenAI 兼容      │ │ Service /  │
│  磁盘md归档) │ │ CameraPicker │ │  Chat Completions)│ │ Geocoder   │
└──────┬──────┘ └──────────────┘ └────────┬─────────┘ └────────────┘
       │                                  │
┌──────▼─────────────────┐      ┌─────────▼──────────┐
│ Documents/diaries/     │      │ LLMConfigStore     │

└────────────────────────┘      └────────────────────┘
```

设计要点：

- **无第三方依赖**：全部系统框架（SwiftUI / PhotosUI / Photos / ImageIO / CoreLocation / Security），包体小、无供应链风险。
- **文件即数据库**：Markdown 文件是唯一持久化事实源，App 启动时解析重建内存索引；任何一台机器上用文本编辑器都能读懂、手改不丢数据。
- **纯函数可测**：请求构造（`LLMService.makeRequest/makeBody/parseResponse`）、Markdown 编解码（`MarkdownDiaryCodec`）、Prompt 拼装（`PromptBuilder`）均为无状态纯函数，单测无需网络与 UI。
- **位置是加分项不是必需**：定位未授权/超时/反地理失败均静默降级，不阻断写日记主流程。

## 3. 核心数据模型

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| `DiaryEntry` | id, createdAt, text, imageFileName?, audioFileName?, locationName?, latitude?, longitude?, isDaySummary, title?, tags[] | 一条日记；isDaySummary 为「当日小结」条目；title/tags 为 AI 生成的标题与标签；audioFileName 为语音日记音频（audio/ 目录） |
| `DiaryDay` | key(yyyy-MM-dd), entries[] | 一天，对应一个 md 文件 |
| `EntryDraft` | image, takenAt, location?, locationName? | 保存前的草稿 |
| `LLMPreset` | id, name, baseURL, model, supportsVision | LLM 接入配置 |

## 4. Markdown 归档格式规范

每天一个文件 `YYYY-MM-DD.md`：

```markdown
# 2026年10月7日 星期三

## 14:30 · 上海市 · 静安区 · 静安公园

![照片](images/IMG_20261007-143000-ab12cd34.jpg)

下午路过静安公园，阳光把银杏叶照得透亮……

---

## 20:05

晚上随手拍的一张照片。
```

规则：

- 一级标题为日期（中文 + 星期），解析时忽略；
- 每条日记一个二级标题 `## HH:mm[ · 地点]`，时间精确到分钟（解析重建 createdAt 时秒归零）；
- 「当日小结」是特殊条目，标题固定 `## 当日小结`，无时间与地点，渲染/解析均排在普通条目之前，createdAt 约定为当天 23:59；
- 图片行格式固定 `![照片](images/<文件名>)`，文件落盘在 `diaries/images/`（最长边 2048px、JPEG 0.85）；语音日记音频行 `![录音](audio/<文件名>)`，文件落盘 `diaries/audio/`（m4a AAC 44.1kHz 单声道，删除条目时随条目清理）；
- 条目之间以 `---` 分隔；正文支持多行；
- AI 生成的标题/标签以标记行存放在图片行之后、正文之前：`title: 银杏叶黄了` 与 `tags: #公园 #秋天`（解析时仅在正文开始前识别，老条目无标记行兼容）；
- 正文与语法冲突的行（`---`、条目标题、`## 当日小结`、图片行、`title: `/`tags: ` 前缀行）渲染时加 `\\` 转义，解析还原；
- 解析对无法识别的行容错跳过（文档标题、游离文本等）。

### 4.1 用户画像文件

| 文件 | 内容 | 写入方 |
| --- | --- | --- |
| `diaries/profile.md` | 基本信息（称呼/简介，用户填）+ AI 画像正文（性格与心理/喜好/日记风格/写作视角提示），头部注释行记录更新时间与信号数 | 用户手改 + 提炼覆写 |
| `diaries/profile-edits.md` | 日记「原文 → 改后」对照记录，append-only，提炼时取尾部 4K 字符 | 编辑日记保存时自动追加 |

画像信号：①修改对照（最有价值，改掉的语气=真实偏好）；②新日记计数；③高频标签/地点统计（提炼时实时计算 Top 8）；④用户自填基本信息。每积累 10 条信号自动后台提炼一次，也可设置页手动触发。

### 4.2 月度回顾文件

`diaries/monthly/yyyy-MM.md`：月记独立于按天日记文件（不参与 DiaryStore 按天索引，由回顾页直接读写）。格式：一级标题「yyyy年M月 · 月记」+ 注释行（生成时间/模型/基于条数）+ 正文，`MonthlySummaryCodec` 容错解析。

## 5. LLM 调用设计

- 端点：`{baseURL}/chat/completions`，POST，`Authorization: Bearer <key>`，60s 无数据超时（流式每收一块重置）；
- 消息：单条 user 消息，content 数组 = 文本块（PromptBuilder 填充后的模板）+ 可选图片块（base64 data URL，上传前缩到最长边 1280px、JPEG 0.7）；「当日小结」支持多图（单图 1024px、JPEG 0.6），prompt 用 `DefaultPrompt.daySummaryTemplate`（占位符 `{count}` `{timeline}`）；
- 流式请求（SSE）支持用户取消：`AsyncThrowingStream.onTermination` 里取消底层网络 Task，取消后保留已生成的部分文本；
- 非视觉预设自动丢弃图片块，退化为「仅根据时间地点写一段」；
- 响应兼容两种 content 形态（纯字符串 / 分块数组）；错误响应提取 `error.message` 展示给用户；
- 默认 Prompt 模板见 `DefaultPrompt.template`，占位符：`{datetime}` `{date}` `{time}` `{location}`（先替换 `{datetime}` 再 `{date}` 避免误匹配）；
- **画像注入**：画像非空时，单条生成与当日小结的 Prompt 末尾统一追加「作者背景与文风」段落（`PromptBuilder.appendingPersona`），不要求模型输出额外字段；自定义模板无需改动即可生效；画像为空完全不影响既有行为；
- **画像提炼**：一次专用纯文本调用（不带图，约 2~4K tokens），输入旧画像 + 基本信息 + 最近修改对照 + 生活轨迹统计，要求按四个固定小标题输出；提炼成功后覆写 `profile.md` 的 AI 画像段并清零待提炼信号计数；
- **月度回顾**：`DefaultPrompt.monthlySummaryTemplate`（`{month}` `{count}` `{timeline}` 占位符），纯文本流式调用（不带图控制 token），timeline 为每天一行「MM-dd 标题或正文首行（≤30字）」上限 40 行；同样注入画像；生成中边写边显，完成后落盘月记文件；
- **语音日记**：转录不走 LLM——系统 Speech 框架实时转录（`SFSpeechRecognizer` zh-CN，`requiresOnDeviceRecognition` 按设备能力开启，转录优先不出本机）；成文走 `DefaultPrompt.voicePolishTemplate`（`{datetime}` `{transcript}`，去语气词/重复，60~150 字）+ 画像注入，纯文本流式；无 Key 自动降级「仅转录」；
- 单条生成要求模型输出 JSON `{"title", "text", "tags"}`：`DiaryGenerationParser` 在流式阶段从部分 JSON 增量提取 text 展示（不破坏流式体验），完成后完整解析；JSON 解析失败整体降级为纯正文（兼容老模板/自定义模板），` ```json ` 代码块围栏自动剥除；

## 6. UI 设计

| 页面 | 内容 |
| --- | --- |
| 首页（日记 Tab） | 大标题「光影日记」；每行 = 缩略图 + 日期标题 + 「N 条记录 · 摘要」；`.searchable` 搜索（正文/地点/日期/标题/标签）；未配 Key 时空态按钮/常驻横幅引导去设置；左上设置、右上 +（拍照/相册菜单） |
| 回顾 Tab | 统计洞察卡（N 天 M 条 · 最常去 · 高频标签）；标签墙（字号/透明度随热度，点按筛选）；足迹地图（MapKit Marker，点标注看当天）；月度回顾列表（生成/查看月记，流式）；空数据时引导空态，无标签/无坐标时对应区块优雅隐藏 |
| 语音录入页 | 大录音钮（录音中红色脉冲 + 计时 + 实时转录）；停止后：保留原声开关（默认开）、「AI 整理/仅转录」分段切换、正文可编辑；权限拒绝/设备不支持时明确降级提示 |
| 新增页 | 照片预览 → 时间/地点元数据 → 自动生成（进度态、可停止）→ 可编辑标题/正文 + 标签胶囊展示 → 保存/取消/重新生成；缺 Key 时给出直达设置入口 |
| 日记详情页 | 条目卡片流（时间·地点 / 图片 / 正文；当日小结为橙色「当日小结」卡片置顶）；条目菜单：编辑、重新生成、删除；右上：当日小结（多图合并生成一篇，可停止）、分享导出当天 md |
| 设置页 | 服务预设、Base URL/模型（自定义时可编辑）、API Key（SecureField，附 DeepSeek 申请链接）、Prompt 模板编辑器（可恢复默认）、用户画像（称呼/简介、画像预览与全文编辑、手动提炼按钮、信号计数状态）、测试连接 |

视觉：系统字体 + 卡片圆角 + SF Symbols，浅色/深色自适应，极简无品牌色。

## 7. 隐私与权限

| 权限 | 用途 | 降级 |
| --- | --- | --- |
| 相机 | 拍照 | 无相机（模拟器）时隐藏入口 |
| 相册（受限即可） | 选照片及读取其时间地点 | 仅影响导入入口 |
| 定位（使用时） | 拍照时记录地点 | 拒绝则日记无地点信息 |
| 麦克风 | 语音日记录音 | 拒绝则隐藏语音功能，引导系统设置 |
| 语音识别 | 语音实时转录 | 拒绝则同上；设备不支持端侧识别时按系统行为并已在权限文案声明 |

- API Key 仅存 Keychain；图片仅用户触发生成时上传给所配置的服务；日记、照片、画像与修改记录全部本地存储，可用文件 App 访问/备份，画像文件可直接删除清零。
