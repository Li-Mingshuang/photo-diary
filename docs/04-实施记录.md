## 3. 关键实现决策

1. **XcodeGen 而非手写 pbxproj**：环境无 xcodegen 时先 `brew install xcodegen`，工程配置全部收敛到 `project.yml` 一个文件，可重复生成。
2. **每预设独立存 Key**：Keychain 单条目存 `[presetID: key]` 的 JSON，切换服务不清空已填 Key。
3. **占位符替换顺序**：先 `{datetime}` 后 `{date}`，避免子串误匹配（单测覆盖）。
4. **时间精度取舍**：md 标题只存到分钟，解析重建时秒归零；单元测试按分钟断言，避免往返精度误报。
5. **模拟器兼容**：无相机时隐藏「拍照」入口，保留「从相册导入」，保证模拟器可完整走通主流程。

## 迭代三（2026-10-08）：AI 生成标题 + 标签

用户提出「照片简短标题/描述和打 tag」，确认后按以下方案实现：

1. **生成侧**：默认 Prompt 改为要求输出 JSON `{"title", "text", "tags"}`（不超过 10 字标题、80~150 字正文、1~4 个标签）；新增 `DiaryGenerationParser`：
   - 流式阶段 `displayText(forPartial:)` 从部分 JSON 增量提取 text 字段展示（含 JSON 转义反转义、末尾不完整转义丢弃），不牺牲流式体验；
   - 完成后 `parse(_:)` 完整解析（剥 ```json 围栏、tags 去 # 前缀、空标题视为无、tags 上限 6 个）；JSON 解析失败整体降级为纯正文，老模板/自定义模板/模型跑偏均安全。
2. **存储侧**：`DiaryEntry` 增加 `title: String?`、`tags: [String]`（老数据兼容，均为默认空）；md 格式新增标记行 `title: xxx` / `tags: #a #b`，放在图片行后、正文前，解析仅在正文（非空行）开始前识别，`title:/tags:` 前缀的正文行纳入转义规则。
3. **UI 侧**：新增页显示可编辑标题 + 标签胶囊（TagCapsule）；详情卡片标题加粗、标签胶囊在正文后；列表行摘要优先用标题；`DiarySearch` 扩展匹配标题与标签（`#xxx` 查询自动去前缀）。
4. **测试**：新增 8 个用例（解析器 JSON/围栏/降级/#前缀/流式部分提取 ×5、标记行往返、标记行转义、按标题/标签搜索），单测 34 → 42。

踩坑：① 测试 raw string 内含 `"#` 序列导致字面量提前终止，改用 `##"..."##`；② 标记行解析条件 `textLines.isEmpty` 未考虑图片行后的空行已入 textLines，改为「无非空文本行」判定。
